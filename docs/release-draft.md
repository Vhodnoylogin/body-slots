# Historical unpublished Nexus draft and current packaging

The retained `0.1.0-alpha.1` Body Slots Nexus draft is a historical mod-author foundation snapshot. Its original `BodySlots-runtime-0.1.0-alpha.1.zip` and `BodySlots-sdk-0.1.0-alpha.1.zip` names, receipts and hashes remain unchanged. [nexus-draft.json](nexus-draft.json) records that October 25 draft and its then-unfinalized licensing; it is not current product metadata. Independently authored source and SDK were subsequently licensed under MIT; see [source provenance](source-provenance.md). The product is now **VR Interaction Framework**. Neither the name change nor the licence update requalifies that old DLL or publishes a file. See the current [game adapter](game-adapter.md) and [naming policy](naming.md).

`tools/package_draft.py` now uses the VR Interaction Framework display name and an explicit allowlist. The runtime ZIP contains the unchanged supplied DLL, a folder README, the MIT licence and portable provenance. It enables no demonstration data and adds no standalone gameplay. The SDK ZIP contains the seven own headers, MIT licence, offline Python author/compiler, optional JSON/.bslots example, a clean read-only discovery utility and API documents. It excludes all test executables/fake SkyrimVR hosts, build objects/PDBs/import libraries, machine paths, reconstructed VRIK code and third-party SDK sources. No Nexus/browser operation is performed by this tool.

```text
python tools/package_draft.py --dll <frozen-activation02-BodySlots.dll> --expected-dll-sha256 a4a5af3b028da5aecdffa6db66e7ef152e2787cd923dcb45518666344eb5a03b --source-commit 376ef62ff05c1e696eff72f11a06ab0469020cc0 --label 0.1.0-alpha.1 --output <new-external-directory>
```

New output is `VRInteractionFramework-runtime-0.1.0-alpha.1.zip`, `VRInteractionFramework-sdk-0.1.0-alpha.1.zip`, `SHA256SUMS.txt` and `draft-artifacts.json`. These are newly generated packages, distinct from historical archives. Archive entries are sorted with fixed timestamps and permissions; identical input bytes produce identical archive bytes. Each archive contains provenance with product display name, payload hashes, production commit and frozen DLL SHA256, without local source/build paths. Packaging-only source changes may remain uncommitted for review and are identified by the packaging tool hash; they do not masquerade as a production rebuild. Technical DLL, install-path, ABI and save identities retain their compatibility names.
