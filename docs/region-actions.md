# Region actions through HIGGS

The separately negotiated [RegionActions1 table](../include/body_slots_region_actions_api.h) connects arbitrary VR Interaction Framework regions to HIGGS's existing input arbitration. A consumer supplies a target anchor, pure eligibility/action proposals and its selected gameplay handler. It does not install a controller callback, reserve a hand itself or run a second fallback when another action wins.

VR Interaction Framework owns the region definition, spatial eligibility, dwell, binding lifetime and contextual revalidation. HIGGS owns actual hand observations, button recognition, provider priorities, the winning grant, suppression of the corresponding native input and physical/transaction outcomes. VRIK remains the body/virtual-pose provider; this region action connection does not require the VRIK-backed player-slot adapter. PLANCK and PPB retain NPC physics and anatomical evidence respectively. This is an implementation contract; the sole architecture concept remains in [Body Pouches](https://github.com/Vhodnoylogin/body-pouches/blob/main/docs/trinity-synergy/concept-en.md).

## Consumer connection

1. Discover `BodySlots_QueryRegionActionsInterface(1, sizeof(RegionActionsApi))`, the ordinary VR Interaction Framework registry/regions tables and the HIGGS hand service. Check every table, version and capability. A missing/incompatible service leaves this integration unavailable; the consumer decides whether its feature requires it. HIGGS itself continues independently.
2. Register a VR Interaction Framework writer and create its named `InteractionRegionSpec` through `RegionsApi.UpsertRegion`. Sphere, capsule, box and flat-cap cylinder shapes reuse the existing geometry service. A slot can use its interaction region; this table does not create another inventory or content store.
3. Register the consumer's own HIGGS client, with the desired default priority. `RegisterBinding` takes that client, the owned region and exact revision, allowed hands, grip/trigger edges, offer callback, execute callback and context. Passing the client explicitly delegates permission for VR Interaction Framework to create/remove this binding's executor and authorize its independent recognizer. The returned registration exposes the executor identity for correlated HIGGS requests and factual outcomes. HIGGS's user overrides still determine priority across providers.
4. Publish copied target anchors with `PublishAnchor`, using the exact previous anchor revision. Preserve the actual target source identity, generation, sample/frame, epoch, save scope and steady-clock time. Publish after observing the real target; an old sample must not receive a new timestamp merely to appear current. Read `CopyIntegration` for the current accepted HIGGS epoch and registry save generation. The caller never publishes a claimed hand position to this action service.
5. The offer callback receives the immutable region observation and exact HIGGS input/snapshot. Return bounded action proposals, including required physical hands, action ID, local priority and grant duration. This callback describes eligibility; it performs no inventory, equipment or physics mutation. HIGGS chooses among all eligible providers, including existing player-slot actions.
6. Only the winning handler is dispatched in HIGGS's main update phase, after fresh context and authority validation. Use the supplied request/grant and the existing HIGGS physical/inventory/transaction services. `Status::Ok` from the handler acknowledges dispatch, not successful gameplay. Report factual HIGGS results after the callback returns, or observe the existing child transaction/physical receipts. The authorized-dispatch fence returns `Pending` for a direct `ReportResult` attempted while its callback is entered.

Local proposal priority orders submissions. HIGGS selects among all eligible providers using its user-configured policy and stable provider/action identity. VR Interaction Framework submits a stable target key derived from the region’s provider and key when several zones offer the same action. Registration order supplies no priority.

## Evidence and lifecycle

The actual hand probe is HIGGS's observed world-space palm, with its original pose identity, generation and observation time. It is not advertised as VRIK's final virtual-hand pose or as hardware freshness. Independent target and palm frame domains are preserved; eligibility requires coherent epoch/save scope and bounded source time skew/age. Target replacement, changed region revision, unavailable tracking, menu/context transitions, held/equipped identity changes, cancellation and world/save resets can invalidate a proposal before execution. An anchor may be retained only within its declared age policy; retention does not refresh its source time.

Recognition refreshes geometry from the exact retained input snapshot and latest published target. Deferred dispatch rechecks the current target and palm under HIGGS's authorized-dispatch fence. Provider callback ordering therefore does not require both sources to claim the same frame number. An ordinary world/body/equipment anchor can back the region; specialized anatomical fitting still belongs to PPB, whose coverage must actually be available.

`RemoveBinding` deactivates the binding immediately. Base `Api.ReleaseClient` also drains that writer's region-action bindings before retiring its registry lease. Callback code/context must remain alive until removal or client release confirms drainage. `Unavailable` when removal is called from a callback means retry outside callbacks before unloading; it is not permission to free the context. Reset invalidates pending contextual work and bars the old HIGGS epoch. Registrations are transient, while authored definitions and existing slot persistence keep their separate owners.

The selected input is not replayed after a failed validation, callback failure or uncertain result. HIGGS owns the consumed Down/Up sequence and claims authorized dispatch once before entering the handler, including failure/exception paths. VR Interaction Framework does not retry another region after selection, release a delivered item as compensation or manufacture a successful content receipt.

Cancellation/removal takes effect before a handler is entered; an already entered handler is drained rather than rolled back. These guarantees cover the participating VR Interaction Framework/HIGGS routes. They do not make an unrelated legacy mod's independent raw-controller hook participate in the broker, or automatically migrate VRIK's original holsters.

## Compatibility and verification boundary

All previous VR Interaction Framework and HIGGS table layouts remain unchanged. This path requires the additive HIGGS authorized-dispatch service in the cooperation fork; released HIGGS001 alone does not provide the complete contract. The existing player-slot content/behavior route and optional native mouth/stash spatial detector remain separate supported consumers of the common HIGGS broker. No generic action handler is installed as a second native consume/stash executor.

The optional `BodySlots_QueryRegionContinuationInterface(1, sizeof(RegionContinuationApi))` subscribes a binding to its original winning press. HIGGS supplies the public selection correlation, request, executor and terminal input. Leaving the region or settling the short grant does not redirect the release. A cancelled sequence and a lost observation have distinct results. Delivery occurs once to the active subscribed binding. A terminal notification grants no mutation authority. The mod supplies its own effect and reports its factual outcome through its private HIGGS executor.

`BodySlots_QueryRegionSourcesInterface(1, sizeof(RegionSourcesApi))` lets the owner of an NPC binding select an exact PLANCK actor/body identity. VR Interaction Framework reads the current main-maintenance capture in the HIGGS post-update phase, validates the independent provider world, actor and body generations, converts metres using the current Skyrim scale, and applies the region’s age/skew limits. Manual target publication conflicts while an owned source is bound. Removal withdraws its observation; an actor/body replacement requires selecting a fresh reference.

`CopyPpbDigestEvidence` provides optional, main-thread, copied PPB revision 2 digest evidence. Specify a PPB NPC form ID, hand, capsule slot, twin and child. The response carries the independent PPB epoch and sequence, available/copied counts and age at read. A missing or truncated grouped record cannot establish physical separation. VR Interaction Framework accepts only PPB’s finger, palm, fist, hand and grab classifiers. It keeps the retained engine-contact flag as reported. Neither a grouped digest nor a live surface read certifies a current PLANCK collision, body generation or an authoritative surface anchor.

Discover HIGGS Hand 2, HandRouting 2, AuthorizedDispatch 2 and InputRoutes 1; the mutation and inventory services are negotiated independently. A client label returned from integration is for delegation and comparison only. Only HIGGS gives the selected executor its private request/grant. Stock HIGGS001 continues to supply the update phase for independent region geometry. See the [NPC pocket example](../examples/npc_pocket_binding.cpp).

Provider tables and the read-only PLANCK client live for the lifetime of the SKSE process. VR Interaction Framework retains copied snapshots across a bounded observation interval. Loading a save or replacing a body invalidates an existing source binding. Removing an action binding drains its gameplay callbacks. The PPB adapter performs a synchronous main-thread copy and registers no callbacks with PPB.

The [production-path fixture](../src/test/region_actions_tests.cpp) links the actual region-action core, region evaluator and HIGGS broker. Full native compilation, exported-table negotiation and offline fixtures are distinct from game qualification. No live installation, SKSE plugin initialization, headset interaction or consumer-mod port is established by these checks.

## Dwell actions in the shared decision window

`BodySlots_QueryRegionDwellInterface(1, sizeof(RegionDwellApi))` adds a separate, size-checked table without changing RegionActions1, its binding record, or any previous table. The public header is [body_slots_region_dwell_api.h](../include/body_slots_region_dwell_api.h). It requires HIGGS HandUseProposals version 2 and its shared-window capability; an older provider returns `UnsupportedVersion` for registration rather than pretending that independent nonbutton rounds share button priority.

A consumer registers its owned region/revision, activation hand, complete resource-hand mask, standard HIGGS use kind, persistent action key, deadlines and two callbacks. The eligibility callback is observation-only. The execute callback receives the current revalidated spatial observation, copied HIGGS snapshot and private selected action authority. It must use HIGGS operations or the appropriate gameplay executor, and remains responsible for factual outcomes. An accepted callback is not a receipt that an inventory, equipment or physics change succeeded. Outcome reporting/ending the use follows HIGGS's dispatch fence and may happen after the callback returns.

Registration explicitly delegates enabling HIGGS shared rounds on the consumer's client as well as registering its executor. Enablement requires all controls released and lasts until that HIGGS client is unregistered, even if this binding is removed. Clients opting into this service must use ordered proposals for new hand uses instead of legacy immediate admission. Register before gameplay input; failure does not fabricate authority. VR Interaction Framework also enables the shared mode on its recognizer at initial connection, so button offers and native eligible actions wait for the same main-maintenance decision window.

Once the configured spatial dwell is ready, VR Interaction Framework submits the provider/action/target candidate to HIGGS. Both orders of button and dwell publication compete by the configured priority before any handler changes state. The selected action key remains separate from the standard physical operation kind. Native acquisition participates in that choice. An already legitimate possession is never preempted; controls without eligible candidates retain the ordinary HIGGS fallback.

Each visit has at most one attempt, including denial, failed eligibility or invalidation after readiness. Only an observed `Outside` rearms the binding. A missing/stale sample, menu transition or world/save reset cancels pending work without treating uncertainty as a new visit. Execution rechecks region ownership/revision, source identity/generation, hand generations and held/equipped identity, source age, save/world scope and menu generation under HIGGS authorized dispatch. A new target sample can update a moving anchor without restarting an otherwise valid visit. An unavailable or replaced source cannot keep an old proposal alive.

Use the ordinary RegionActions1 removal, anchor publication, observation and RegionSources APIs for the returned binding. Removal deactivates the binding and cancels its undispatched proposal; an entered callback drains before its context may be freed. The game adapter, SDK fixture and actual HIGGS broker tests are separate from Skyrim gameplay qualification. This addition does not migrate a consumer mod automatically, add anatomy, create physical hand states or alter PLANCK/PPB ownership.
