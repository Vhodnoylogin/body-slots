# Anchoring a region to a PLANCK actor body

A pickpocketing mod can place its own interaction region on an NPC pelvis. PLANCK supplies the body's sampled pose. Body Slots evaluates the mod's region against the HIGGS palm, and HIGGS grants the action. The helper publishes only a target transform. The region, item selection and crime rules still belong to their respective owners.

Compile the [helper](../examples/planck_region_anchor.cpp) and its [header](../examples/planck_region_anchor.h) into the consumer, with the Body Slots headers, HIGGS public hand header and PLANCK revision 2 header containing `CopyActorSampleTime`. At runtime obtain the provider table through PLANCK's official message transport. The helper requires a 136-byte or larger version 2 table with actor snapshots and the sample-time capability. PLANCK builds exposing only the earlier table cannot provide an eligible anchor.

1. Register a PLANCK client, a Body Slots NPC region and a new action binding for that region. The writer owns the binding and its executor. Use one serial publisher for this binding, starting with anchor revision zero.
2. Select the actor and body through `CopyActorPhysics`. Retain the **entire** body reference including the PLANCK epoch and both generations. Read `RegionActionsApi::CopyIntegration` for the current HIGGS epoch and registry save generation. Pair these observations only after your game lifecycle handler has established that both providers describe the same loaded world. Their numeric epochs are independent. Construct `PlanckRegionAnchor` with this target, the current inverse Havok world scale (Skyrim units per metre) and the allowed sample age in nanoseconds.
3. Call `Update` in the consumer's update phase with caller-owned scratch storage for the actor's bodies. It reads the actor, checks the selected body's identity, and asks PLANCK for the exact sample's monotonic capture time. The first eligible sample must have been captured after construction. Re-reading that sample does not extend its age. Region-local dimensions use Skyrim units. The transform converts translation from metres and the world-from-body quaternion to a row-major rotation.
4. A missing capability, failed exact-time lookup, stale pose, regressing frame, replaced body or changed destination scope withdraws the previous eligible anchor. The v1 publication contract clears an invalid sample at the current revision and retains its high-water marks. Check every returned status, including withdrawal errors. Call `Withdraw` when the target becomes unavailable, then remove the binding and drain callbacks before releasing its owning clients. On rebinding, establish a fresh body, binding and world association.

The adapter uses an observed physical body as an anchor. A body index alone does not identify an anatomical pocket. Anatomical selection may use PPB, while logical pocket placement and interaction eligibility belong to Body Slots and its consumer. The HIGGS palm and PLANCK target may update at different rates. Body Slots applies the region's timing and skew rules at arbitration.

To include the check in the regular Body Slots CTest build, set `BODY_SLOTS_PLANCK_SDK` to a PLANCK source checkout that exposes the timestamp capability. Build the `body_slots_planck_region_anchor_tests` target and run `ctest -R body_slots_planck_region_anchor`.

The [offline check](../src/test/planck_region_anchor_tests.cpp) exercises the actual PLANCK registry with synthetic poses and a recording Body Slots publication table. It covers unequal provider epochs, capture time, a rotated body in metres, revision ownership, stale data, API negotiation and replacement. The helper is opt-in consumer source. Runtime behavior in Skyrim still needs testing.
